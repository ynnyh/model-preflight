# Model Router（极简版）

任务开始前跑**一次**判断，只回答三个问题：**用什么模型、什么思考强度、完成后是否需要测试**。

## 任务描述模板（阶段一：先补齐，后判断）

**信息不足不做判断**——判断质量的上限由输入决定，空泛的描述只会得到空泛的建议。
用户说任务后先对照模板补齐，缺什么问什么（**一轮问完，不挤牙膏**）：

```
任务：<要做什么，一句话>（必填）
完成标准：<怎样算做完，如"功能跑通" "补上单元测试">（必填）
背景：<哪个项目/模块，相关约束>（可省略）
```

- 缺「任务」或「完成标准」→ **不跑判断**，先追问补齐；
  用户明确说"你定/就这样"才按假设判断，并在建议里列出所依据的假设。
- 「背景」缺失 → 可按合理假设判断（给建议时说明假设即可）。

## 起手式（仅显式触发，不自动执行）

用户说「**preflight**」「**航前检查**」时，对相应任务执行完整航前流程（补齐 → 判断 → 停等）；
用户说「**postflight**」「**航后检查**」「**看看这次改动**」时，执行航后检查（见下文）。
**仅此显式触发，此外不要主动跑判断**——用户直接说任务就正常干活。这是自然语言触发词，不依赖
宿主的斜杠命令机制——支持自定义命令的 agent（ZCode / Claude Code / Codex）可另配
/preflight 与 /postflight 命令作为快捷方式。

## 流程

**阶段一（补齐）**：按上面对齐任务描述。

**阶段二（判断）**：跑：

```
python scripts/route.py --text "<任务描述>" --env <环境名> --human
```

环境名 = 本 skill 被哪个 agent 加载（`~/.zcode/skills`→`zcode`，`~/.codex/skills`→`codex`，
`~/.claude/skills`→`claude`）；输出的人话三行就是三个答案。
把三个答案告诉用户（例："建议 GLM-5.3 + 最高思考；完成后需要测试验证。请切换后回复'开始'"），
**本轮随即停住、不执行任务**。会话主模型与思考强度是用户在客户端的选择，agent 无工具修改。

**阶段三（执行）**：当前模型已是建议档位 → 零操作直接开始；用户切换后回复"开始" → 干活。
完成后：判断为需要测试 → 做测试验证再收尾；否则直接收尾。**收尾汇报默认附一张改动小账单**
（`git diff --stat` 的文件级统计；非 git 目录则按修改时间列最近改动的文件）——账单只是展示，
完整 diff 内容按航后检查显式触发。会话开始后主模型不再切换（会话中切模型丢上下文/费 token）。

## 航后检查（postflight，显式触发）

用户说「postflight」「航后检查」「看看这次改动」时执行。目的：让用户**验收**实际改动
（范围对不对、内容是否匹配任务、有无意外影响）。全程只用当前会话模型跑 git 命令并叙述，
**不调用 Jev、不产生任何额外模型调用**：

1. 看**未提交的工作区改动**（`git status` + `git diff --stat`）——刚干完活通常未提交；
   工作区干净时先问用户：看最近一次提交（`git diff HEAD~1`）还是指定范围，不猜。
2. diff 总量 ≤ 约 200 行 → 完整展示；更大 → 只给 `--stat` 账单 + 改动文件清单，
   问用户要细看哪个文件，按需展示。
3. 用人话汇报三件事：改动范围（是否只动了该动的文件）、与任务的对应关系、值得注意的点。
4. 非 git 目录 → 明说，退化为按修改时间列出最近改动的文件。

## 判断标准（降级时照此逐项对照）

- **模型档位**：`no_llm` 纯规则查表即可 / `fast_small` 改写、提取、分类、格式转换 /
  `balanced` 常规生成与理解 / `reasoning` 多步推理、代码、数学、复杂规划。
- **思考强度**：不开（直接回答即可）/ 低（需权衡多因素组织回答）/ 高（须逐步推理、验证中间结果）。
- **是否需要测试**：改动涉及逻辑、边界、核心路径 → 是；纯文档、注释、文案 → 否。

## 依赖与降级

- 判断由 TypeSafe Jev 完成（`TYPESAFE_API_KEY` 环境变量）。
- **无 key 降级协议**：判断者换成当前会话模型，流程与标准不变——
  1. 阶段一补齐任务描述照旧（与 key 无关）；
  2. 按「判断标准」逐项对照，自行给出三答案（不拍脑袋）；
  3. 三行建议开头标注**「（降级判断）」**；拿不准**往高档保守建议**；所依据的假设一并列出；
  4. key 配好后自动切回 Jev，流程零改动。
- 输出的 model/thinking 依赖 `~/.config/model-router/config.json` 的环境映射；
  当前环境无映射时先跑 `scripts/setup.py --env <环境名> --interactive` 补齐。

## 可选增强（默认不用，在 scripts/optional/）

- `call.py`：子任务按判断结果换模型执行（需要执行方 API key，如 ZHIPU_API_KEY）。
- `review.py`：多维复盘（完成度/风险等）。
- 需要时把 scripts/optional/ 里的脚本移回 scripts/ 并按其文件头说明使用。
